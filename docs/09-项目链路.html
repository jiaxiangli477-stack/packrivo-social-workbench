四、生图：模型、参数、落盘、怎么发出去

环节具体做法
提示词有 content.image_prompt 就用；没有则 chat(task=analyze) 生成 60–90 词英文提示词（产品 + 场景 + 光位 + 留白 + 4:5），顺带产反向词
本地出图ComfyUI 127.0.0.1:8188 + SD1.5（v1-5-pruned-emaonly）：KSampler steps 25 / cfg 7 / euler / normal，819×1024，约 55–70 秒/张
为什么不用 SDXLSDXL-turbo 权重 6.6G，这台 6G 显存加载即崩（access violation）；SD1.5 稳定，代价是产品细节偏「氛围图」
外部出图设置里填 image_api_base/key/model → POST {base}/images/generations（OpenAI 兼容，response_format=b64_json）；配了外部就优先走外部
落盘data/media/gen-*.png（本地）或 api-*.png（外部）；DB 写 content.image_path / image_alt / image_prompt
发布时Bluesky：uploadBlob 上传 → 卡片 thumb；Telegram：sendPhoto 带 caption
批量POST /api/images/batch {limit:10} 后台串行跑，UI 每 4 秒轮询 GET /api/images/batch 显示 进度/成功/失败

五、数据怎么跟踪

层字段 / 端点说明
发布结果publish_result: ok、channel、platform_post_id、url、error_class、detail成功才有 URL；失败归因（pending_config / upstream_error / auth_failed）
指标表metric: content_id, platform, day, impressions, likes, comments, shares, saves, clicks, sessions, orders_amount, inquiries, sourcesource = demo / manual / ga4
录入POST /api/metrics数据看板有表单，按天回填
聚合GET /api/metrics/overview?days=30总量 / 按平台 / 帖子排行（含询盘）/ 互动率 / CTR
归因UTM：utm_source=平台&utm_medium=social&utm_campaign=产品slug-YYMM&utm_content=c{id}与 content.id 一一对应，能倒查是哪条稿带来的
现状缺口指标目前靠手填；平台侧点赞/曝光没有自动拉回GA4 未授权；下一步可加「定时回捞 Bluesky/IG 互动数」

六、数据表（SQLite · data/workbench.db）

  • content 稿件：平台/标题/正文/标签/UTM/状态/配图/父稿
  • review 审核记录（AI/人工）
  • schedule 排期（state: pending/queued/published/failed）
  • publish_result 发布结果（真实 URL / 错误归因）
  • metric 每日指标（曝光/互动/点击/询盘，source=demo|manual|ga4）
  • radar_snapshot 情报快照（含 kimi 质检结果）
  • radar_seen 已看过的 URL（换一批去重）
  • hashtag 标签池（平台×层级×权重）
  • platform_tag_policy 每平台标签配额/字数/链接方式
  • credential 凭据（DPAPI 包密钥 + AES-GCM）
  • product / kb_item / account / audit_log
