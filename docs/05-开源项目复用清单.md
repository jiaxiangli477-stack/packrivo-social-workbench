## 五、许可证这一条必须提前说清

你后面要「卖给别人」，许可证直接决定能不能卖：

| 许可 | 项目 | 你能做什么 |
|---|---|---|
| MIT / Apache-2.0 | cogsend、Crawlee、PocketBase、umami、browser-use | 可闭源商用，保留版权声明即可 |
| **AGPL-3.0** | **Postiz、Listmonk、brightbean、firecrawl** | 自己用没问题；**一旦你把它改成自己产品对外提供网络服务，就必须开源你的修改**。想闭源卖，只能把它当独立服务调用（不改它的代码、只通过 API/MCP 交互），或者换 MIT 方案（如 cogsend） |
| Unlicense | yt-dlp | 随便用 |

结论：**Postiz / Listmonk 这种保持原样独立部署、只调 API**，不要 fork 改内部代码——这样既不触发 AGPL 的传染，又能白拿功能。

结论（对这台机器而言）：

1. **适配器先写、本体后装**。已经按公开 API v1 把 `channels.postiz` 写完并自测 21 项全过 —— 这样无论最后跑哪个版本，前端只换 Base URL + Key。见 README「发布中心：Postiz 真发适配器」。
2. **Postiz 本体的三条落地路线**，按代价排：
   - A. 装 Docker Desktop（要 WSL2 + 管理员 + 重启一次）：`git clone gitroomhq/postiz-docker-compose` → 填 `.env` → `docker compose up`，这是官方路径，最省心。
   - B. 本机裸跑（不需要管理员）：便携版 PostgreSQL 17 zip（`initdb` 后 `pg_ctl start`）+ Redis for Windows（tporadowski/redis release zip）+ Node 22（Postiz 要求 `^22`，本机 24 不一定行）→ `pnpm install && pnpm run dev`，Next 4200 / 后端 3000。装完两个服务后能跑，但 Node 版本这条要先试。
   - C. 放到有 Docker 的另一台机器或云主机上，只把 `api/public/v1` 暴露给本机（Postiz 有 CORS/鉴权，不开放 UI 也行）。
3. **许可证纪律不变**：Postiz / brightbean / trypost / openpost 都是 AGPL-3.0 —— 独立部署、只调 API 不触发传染；要改它内部代码再对外提供网络服务，就得开源。
