# Packrivo 外贸社媒工作台（本地版 v0.1）

单机可跑的外贸社媒内容工作台：**爆款入库 → 拆解结构 → AI 一稿多平台 → 审核 → 排期发布 → 结果归档**。零第三方依赖（Node 24 内置 `node:sqlite`），双击 `启动.bat` 就能用。


## 桌面快捷方式（最省事的打开方式）

桌面上有两个快捷方式：

| 快捷方式 | 作用 |
|---|---|
| **Packrivo 工作台** | 服务没开就自动启动（后台隐藏进程），等健康检查通过后直接打开浏览器 `http://127.0.0.1:8795` |
| **Packrivo 停止服务** | 只停 8795 端口那个 node 进程，不影响其它 node 程序 |

实现：`service/open.ps1`（探活 → 起服务 → 打开浏览器）、`service/stop-all.cmd`（按端口杀进程）。
启动脚本用 `ProcessStartInfo` 直接拉 node，不弹控制台窗口；关闭浏览器不会停服务。
需要重新开始只需再双击「Packrivo 工作台」，已运行时会直接打开页面。

## 发布中心：Postiz 真发适配器（2026-10-26）

契约不是猜的：从 `gitroomhq/postiz-docs` 的 `public-api/openapi.json` 取，端点、鉴权头、请求体、各平台 `settings` 全部按官方定义实现。

| 项 | 实现 |
|---|---|
| 端点 | `GET {base}/integrations`、`POST {base}/posts` |
| Base 归一化 | 裸地址自动补 `/api/public/v1`（自建）；`https://api.postiz.com` 补 `/public/v1`；已带全路径不重复拼 |
| 鉴权 | `Authorization: <api key>`（裸 key，不是 Bearer） |
| Key 存储 | AES-256-GCM 加密进 `credential` 表（`owner_kind='channel'`），主密钥 DPAPI 包；页面只回显后 4 位 |
| 通道匹配 | 按 integration `identifier` 自动匹配（`x` / `facebook` / `linkedin`+`linkedin-page` / `instagram` / `tiktok` …）；也可用 `postiz_integration_map` 手工指定 id |
| 提交方式 | `postiz_type=now`（默认，工作台到点发）/ `schedule`（把 `run_at` 交给 Postiz）/ `draft`（只建草稿） |
| 平台 settings | X 补 `who_can_reply_post`；IG 补 `post_type`；TikTok 补 8 个必填项；Pinterest 必须给 `board`；YouTube 必须 2-100 字标题；Reddit/Lemmy 必须给 `subreddit`；缺项在本地就拦下并写明填哪 |
| 错误分类 | 401/403 → `pending_config`（Key 不对）、404 → `pending_config`（Base 路径错）、429 → `rate_limited`、连不上 → `upstream_error`；前两类直接 `blocked` 不重试 |
| 缺素材 | Instagram / TikTok / Pinterest / YouTube 无媒体 → `pending_media`，`blocked` 并写原因 |

接口：

```
GET  /api/channels/postiz           当前配置（base 归一化后、key 是否已存、提交方式）
POST /api/channels/postiz/key       {key}  加密存 Key，返回 hint
POST /api/channels/postiz/verify    真连一次 /integrations，返回通道清单 + 哪个工作台平台匹配上了哪个通道
POST /api/channels/postiz/draft     {content_id, account_id} 只在 Postiz 建草稿，不对外发
```

node ops\postiz-stub.mjs          # 单独起桩，手工在页面里配 http://127.0.0.1:8798 + stub-key-123 也能点验证

## 换一批 / 主题 / 帖子源（本轮新增）

- **换一批**：视频、帖子、文章三个子版块各有按钮。走 `POST /api/radar/reroll {scope}`，只抓条目、跳过已看过的 URL（`radar_seen` 表去重），并同样送 kimi 复审；没有新内容时如实提示「保留当前这批」。实测一次约 60 秒。
- **深色/浅色**：右上角「浅色 / 深色」切换，存 localStorage；也可用 `?theme=light` 直接进浅色。
- **帖子源**：新增 **Bluesky**（`api.bsky.app` 公开搜索，带赞/转/回复与配图），与 Mastodon、Lemmy 并列。三个源都加了互动门槛（Mastodon/Bluesky ≥3，Lemmy ≥10）与行业词硬过滤。
- **已排除**：Pinterest（`BaseSearchResource` 返回 403 Invalid Resource Request，需要签名 cookie）、Pixelfed（各实例返回 401 Unauthorized）、Tumblr（API 需要 OAuth key）。这三家目前没有可用的公开搜索接口，不硬凑。
- **kimi 审查分块**：条目按 10 条一批送审，避免长输出被截断；换一批也走同一套审查，实测 12 条视频全部拿到评分与判定。

## kimi 质检（每条内容都要过审）

雷达刷新最后一步：把抓到的视频/帖子/文章 + 全部关键词送 `kimi-k3.1-pro`（`llm_task_models.audit`）打分：

- 0-100，80+ 直接可用、60-79 一般、<60 判 `drop`；每条必须给一句理由。
- 条目与关键词两批分开审，顺序执行 + 空结果重试（并发时偶发返回空）。
- 结果落在快照的 `audit` 里，页面顶部显示「kimi 已审 N 条 · 丢弃 M」+ 一句总结。
- 被判 `drop` 的默认不显示；全被丢时给出「谁被丢、为什么」的清单，而不是一句「没抓到」。

实测（2026-10-25）：27 条目 + 50 关键词，**19 keep / 8 drop**，丢弃理由包括「投融资新闻没有可借鉴结构」「牛皮纸上的个人艺术创作，与包装无关」「仅牛皮纸胶带教程，与 B2B 采购无关」。

## 热度门槛与关键词口径

- 帖子：Mastodon 赞+转+回复 < 3、Lemmy 顶+评论 < 10 的直接不进候选池（没有热度的不进）。实测 9 条降到 3 条，再被 kimi 全部判掉——Mastodon/Lemmy 确实没有合格的包装 B2B 帖子，页面如实显示 0 并列出理由。
- 关键词：**没有免费的搜索量接口**。用「联想位次 + kimi 相关性分 + Google Trends 外链」替代，表格里明确标注；要真实月搜索量得接 DataForSEO / Ahrefs / Keywords Everywhere 的付费 Key。
- 同行网站：从 ARTEX 任务 #9 的《06-类目情报》（20 个域名，逐个 HTTP 核验过）灌进来，本轮实测 **15 个抓取成功、5 个失败**（被 Cloudflare 拦或超时），失败原因记在 `errors` 里。

注意：完整刷新（含 kimi 两轮审查）现在约 **4-5 分钟**，主要花在 20 个竞品站点抓取 + 两次 kimi 调用上。下一步可以拆成「快刷新（不审）」和「深审」两个按钮。

## 知识库（AI 越用越懂你）

导航「知识库」，七类条目：品牌 / 产品 / 目标客户 / 语气 / 术语·卖点 / 禁用·避免 / 案例。

- 每条有标题、内容、权重、启用开关；停用即不参与生成。
- **生成、审核、AI 分析三处都会自动注入**（`kbContext()` 拼进 prompt，按权重排序，截断到 3500 字符）。
- 实测：加了「克重写 gsm、尺寸写 cm、MOQ 用 pcs」和「禁用 100% 可降解 / FSC 编造 / 折扣码」后，新生成的稿子自动写成 `300 gsm`、`MOQ 500 pcs`，标签带上 `#Packrivo`。

## AI 分析（每条内容 / 每条爆款，单点触发）

**内容**：「审核队列」每张卡右上角「AI 分析」→ SEO 与 GEO 双评分、问题清单、改法、建议关键词、建议标题、可直接照改的点。

- SEO 看：关键词是否进标题与首句、标签数量与相关性、CTA 与落地页、采购意图词。
- GEO（生成式引擎优化）看：实体是否明确（品牌/产品/材质/规格）、有没有能被 AI 直接摘走的结论句、事实密度、是否分点、规格是否可核验。
- 实测一条 Instagram 稿：SEO 82 / GEO 86，列出「标题缺 custom mailer box 关键词」「缺 CTA」等，并给出改写标题。

**爆款**：「爆款库」每行「分析」→ 为什么火（带依据）、打的是谁、可复用结构点、照搬的坑、买家用 AI 搜时会问的问题。

接口：`POST /api/analyze {target_kind, target_id}`、`GET /api/analyze?target_kind=&target_id=`、`/api/kb` 增删改查。
分析固定走 `space-bunny`（`llm_task_models.analyze`）——step-5-preview 这类思考模型会把 9k 字推理塞进正文，JSON 被挤掉，实测换模型后稳定出结果。

## 模型接入说明

- 默认走本机网关 `http://127.0.0.1:8787/v1`（OpenAI 兼容）。
- 「设置 → llm_task_models」把任务映射到模型，例如：
  `{"deconstruct":"deepseek-v4.1-flash","rewrite":"deepseek-v4.1-flash","review":"step-5-preview","report":"space-bunny"}`
- 自定义接口在「模型接入」页添加，按优先级升序作为主备链，主接口失败自动降级。
